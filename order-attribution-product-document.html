01 / DECISION SUMMARY

先保存订单归属事实，再生成统计模式

主方案 · 待 G2 确认

新旧方案的关键差异不在统计名称，而在数据模型。单一、可修改的“所属部门”无法同时证明最初成交归属、当前货物归属和中间扭转过程。新模型将不可变事实、可变化事实、受控派生和最终标签分开。

推荐模型

双层归属 + 四类互斥模式

成交归属不可变，当前货物归属随正式事件更新。先比较两者判断单向扭转；未扭转时再按买家 / 非买家中标方分类。

仍需确认

优先级与事件来源

Q-007 确认扭转是否优先且四类互斥；Q-008 确认当前货物归属以哪个正式事件为最终依据。

01

扭转双向并存

自营转生态和生态转自营没有优劣，是同一条归属变化规则的两个方向。

02

统计唯一

同一订单同一时点只生成一个统计模式，四类统计桶不重复。

03

标签唯一

统计模式不替代当前业务标签；一个订单仍只有一个当前业务标签。

04

原始标签不变

归属扭转结束后，原始成交标签仍永久保留。

02 / PROBLEM DEFINITION

实际要回答的四个事实问题

当业务询问“这个订单应该算谁”时，不能从最终标签反推。系统需要直接回答成交时归谁、现在归谁、是否跨部门、无扭转时谁中标。

子问题对应事实不能回答时的后果
成交时归谁成交归属无法证明原始来源，也无法判断是否扭转
现在货物归谁当前货物归属报表无法反映真实物权和当前部门
是否跨部门扭转扭转方向扭转订单可能被重复计入买卖家中标
无扭转时谁中标中标方买家中标与非买家中标无法互斥
根因判断

订单标签混乱的根因不是标签名称不够多，而是成交来源、货物当前归属、统计口径和业务标签共用了相似的“部门”概念，却没有独立的数据边界。

04 / FOUR MODES

四个模式是一组互斥枚举

两个扭转方向必须同时存在。它们描述的是成交归属与当前归属的净变化，不是需要二选一的产品方案。

MODE 01 · 扭转优先不限中标方

自营扭转为生态

成交归属为自营，当前货物归属为生态，货物在两个部门之间发生净扭转。

原始标签保持“闪回-闪回成交”
MODE 02 · 扭转优先不限中标方

生态扭转为自营

成交归属为生态，当前货物归属为自营，货物从生态流向自营。

原始标签保持“买家-买家成交”
MODE 03 · 无扭转中标方：买家

买家中标订单

成交归属等于当前货物归属，且正式事实中的中标方为买家。

保持成交时原始标签
MODE 04 · 无扭转中标方：非买家

非买家中标订单

成交归属等于当前货物归属，且中标方为买家之外的其他受控主体。

保持成交时原始标签
05 / DECISION RULES

先判扭转，再判中标方

这是本稿的主推规则。扭转订单已经拥有独立统计桶，必须停止后续买卖家中标判定，才能保证互斥。

非买家中标订单

不猜测、不默认，保留原快照

待归因
IF 成交归属 = 自营 AND 当前货物归属 = 生态 → 自营扭转为生态 ELSE IF 成交归属 = 生态 AND 当前货物归属 = 自营 → 生态扭转为自营 ELSE IF 成交归属 = 当前货物归属 AND 中标方 = 买家 → 买家中标订单 ELSE IF 成交归属 = 当前货物归属 AND 中标方 = 非买家 → 非买家中标订单 ELSE → 待归因

11 / METRICS & ROLLOUT

先影子计算，再切换报表口径

STEP 01

影子计算

生产事件只读取和计算，不改写现有报表，与旧口径并行比对。

STEP 02

治理待归因

补齐归属事件、中标方枚举、幂等键和责任系统。

STEP 03

灰度启用

选择新订单或指定范围使用新口径，保留旧报表与回滚能力。

STEP 04

正式切换

业务、数据和研发确认后启用四类模式，并记录口径版本。

量化边界

当前没有可核验基线，本稿不编造自动命中率、归因完整率或处理时延目标。基线由数据负责人补充后再形成量化验收。

12 / REVIEW & GATE

本轮评审需要关闭的问题

  • Q-007
    四类统计模式是否按扭转优先、彼此互斥？

    本稿按“先判自营 / 生态双向扭转，再判买家 / 非买家中标”成稿，等待业务确认。

  • Q-008
    当前货物归属以哪个正式事件为最终生效依据？

    需明确来源系统、业务生效时间、幂等键、晚到和回退处理。

  • NEW-01
    多次流转是否按当前净结果判定？

    建议四类模式只看当前净状态，中间流转保留在时间线，不新增第五类。

  • NEW-02
    中标方枚举如何映射非买家？

    需确认渠道、平台、审单等主体归入“非买家”的统一映射。
