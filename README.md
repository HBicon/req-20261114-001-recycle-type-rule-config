## 核心机制

- 订单成交时写入不可变原始标签：自营为 `闪回-闪回成交`，生态为 `买家-买家成交`。
- 新建业务标签时，适用部门只能在自营、生态中单选；历史共用标签保留查看与双方审核。
- 标签分类包含“指定手机号”和“企业购”；机器人成交、渠道成交、指定手机号需填写对应明细。
- 分类绑定值进入审核摘要与标签详情，手机号在公网原型中始终脱敏展示。
- 分类字典不提供“自定义业务”；保值换新、企业购在同一部门只允许一个启用或待审核配置。
- 同一渠道、手机号或机器人只能绑定一个生效标签；已占用选项禁用，提交与发布均再次校验。
- 当前业务标签初始化为原始标签，任一时刻只允许一个值。
- 命中已审核生效规则后只更新当前标签；无命中时保留原始标签。
- 多条规则命中时数值更大的优先级胜出；规则构建器提供执行优先级配置、快捷调整、滑块和本部门排序预览。
- 同部门、同优先级、条件可重叠且目标不同时禁止发布。
- 提交人与审核人分离；共用标签必须获得自营、生态双方确认。
- 首期人工变更只允许经审批的异常修复或规则重算。
- 新规则默认不追溯历史订单，只影响新订单及后续登记事件。

## 后台界面基线

本原型采用 **Ant Design Pro v6.0.3 / ProLayout** 的侧边布局信息架构，并通过 `_shared/admin-shell` 的零依赖静态壳层落地：

- 左侧菜单：`240px`，可收起为 `64px`。
- 移动端：小于 `992px` 自动切换为 `260px` 抽屉。
- 顶栏：`56px`，统一承载环境、全局操作和账号信息。
- 菜单分组：工作台、配置、规则与事件、验证与追溯。
- 当前页面：菜单选中态、顶栏页面名、面包屑三者同步。

共享规范见 `../_shared/admin-shell/README.md`，正式 React 工程应直接使用 `ProLayout`，不另建菜单结构。

## 可体验流程

1. 在“业务标签”查看受保护的原始标签，新增标签时验证部门单选、分类联动、非录入分类唯一、绑定值唯一与手机号校验。
2. 在“标签规则”打开执行优先级配置区，验证输入、`±10`、滑块、排序预览和实时冲突阻断。
3. 在“审核与发布”切换评审角色，完成共用标签的自营、生态双部门确认。
4. 在“规则试算”验证自营多机器人、生态企业购、生态售后退货和无规则命中。
5. 在“订单追溯”发起异常修复，确认审批前当前标签不变，审批通过后才更新。
6. 在“运行与权限”查看事件契约、失败兜底、角色权限矩阵和审计流水。

## 交互边界

- 所有名称、编码、手机号、订单号和渠道均为脱敏演示数据。
- 渠道编号不在公网版本展示；原型使用脱敏渠道名称。
- 数据保存在浏览器 `localStorage`，仅用于原型演示。
- 不连接真实订单、售后、结算或物权系统。
- 重置按钮可恢复初始演示数据。
